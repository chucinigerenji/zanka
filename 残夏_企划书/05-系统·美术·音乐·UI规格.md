# 系统 · 美术 · 音乐 · UI 规格

---

## 一、玩法循环

```
【日历界面】→ 选择时段与地点 → 【场景：ADV 对话 / 轻探索】
      ↑                                    ↓
   【信件系统】←── 【章节结算】←── 【照护日志结算】
```

1. **不是点击式解谜，也不是数值养成**。操作极简：选择「今天去哪里」。
2. 探索要素克制：每个场景 2–4 个可调查点（不给奖励道具，只给**记忆碎片**——一段文字、一个声音、一张照片）。
3. 每章结算展示三样东西：**与栞的回忆点 / 她的收支 / 祖母的照护状态**。
   → 玩家第一次看到「她的收支」是负数时，会自己明白过来。

## 二、四个核心 UI

### ① 日历 + 潮汐表（主界面）
- 月历形式，每天标注：潮位、满潮/干潮时刻、大潮/小潮
- **潮汐数据从序章就完全公开**——包括终章那天的「涨潮提前 1 小时 20 分」
- 玩家从不觉得那是伏笔，只以为是背景设定

### ② 时间编排（时段分配）
- 每天 3 格 → 逐章递减至 0
- 递减**不做任何说明**。只在她某天说「我今天有点累，先回去了」之后，格子少一格

### ③ 照护日志（祖母线）
- 每天 2 分钟的真实操作：分药、记录饮水、查看有没有走失
- **介护保险申请表要让玩家真的去填写**（下拉选项、要盖章的位置、要填错的字段）
- 这不是「有趣的玩法」，这是**体验设计**——让玩家亲身感受「照护是一份没有工资的工作」

### ④ 不会寄出的信
- 每章末出现。给玩家 3–4 个片段选项，选一个写进信里
- 信件收藏在「抽屉」UI 里，可以随时回看
- 全部 6 封信在终章拼成遗书 → **每个玩家的遗书都不一样**
- 全收集解锁隐藏对照文本：**栞在同一天的日记**

## 三、演出规格（本作最核心的技术差异点）

### 「病征演出」系统
**不给任何数值和提示**，只用视听语言让玩家自己学会「读懂她的身体」：

| 阶段 | 演出 | 出现时机 |
|---|---|---|
| 1 | 对话中，她的立绘呼吸起伏比其他人慢 0.3 秒 | 第一章起（玩家初期不会注意） |
| 2 | 画面边缘极轻微的高频抖动（<2px），持续 1 秒 | 第二章起，她上楼、走远路之后 |
| 3 | 环境音里加入极轻的耳鸣音（4kHz，-30dB） | 第三章起 |
| 4 | 所有声音（含语音）瞬间闷掉 0.6 秒 | 第四章起 |
| 5 | 屏幕四周轻微暗角收缩 | 第五章 |

> **二周目重看第一章会毛骨悚然**——原来从第 12 分钟起，她就一直在喘。

### 其他演出
- 立绘不换表情时也会有微动（Blink / 呼吸 / 重心移动），《千恋万花》级别的日常演出密度
- 雨天场景叠加玻璃水痕；台风场景做**风的物理位移**（立绘头发与衣角）
- **BGM 停止规则**：剧本标注 `[MUTE]` 的场景一律静音，共 14 处，其中 3 处是全局情感最高点

## 四、技术方案（Godot 4.x）

| 项目 | 方案 |
|---|---|
| 引擎 | Godot 4.3+，Forward+ 渲染，目标 60fps |
| 对话系统 | **自研 YAML/自定义 DSL**（不用 Dialogic，因为要支持「信系统」与「双视角对照」这种非标准结构） |
| 脚本格式 | 类 Markdown 的 `.scene` 文本（策划可直接写，不用碰代码），示例见下 |
| 分支管理 | 状态机 + 全局 flag 表（JSON），支持热重载，脚本改动不用重启游戏 |
| 存档 | 自动存档（每时段）+ 手动 3 格 + **跨周目继承**（Memory 碎片、信件、CG） |
| 本地化 | 全文本走 CSV → 导入为 Godot Translation；字体需支持中文、日文（思源宋体/黑体子集化） |
| 平台 | PC(Steam) 1080p/4K 缩放 → Android（横屏，19.5:9 适配）→ Switch |
| 性能 | 2D 场景 + 立绘分层，中端手机可跑；CG 用纹理流式加载避免内存峰值 |

**脚本 DSL 示例**
```yaml
scene: ch03_typhoon_workshop
bg: bg_factory_interior_evening
bgm: null            # [MUTE]
chars: [shiori_rain, yuto]
---
shiori: 「我想活到冬天。」
yuto: 「……什么？」
shiori: 「没什么。我想看雪。」
fx: breath_slow(1.0)
wait: 2.0
log: 第三封信
```

## 五、美术规格

| 资源 | 数量 | 规格 |
|---|---|---|
| 立绘（角色） | 7 人 | 每角色 3 姿势 × 5 表情 × 2–3 服装，PSD 分层，4K 制作 |
| 背景 | 约 40 张 | 1920×1080，含昼/夕/夜/雨/台风变体（变体算 0.3 张成本） |
| 事件 CG | 60–75 张 | 关键场景全 CG；含差分（表情、雨、时间） |
| 潮汐/海面 | 1 套 shader | 程序化海面 + 潮位参数化（**用同一条海，表现从满潮到干潮的全部状态**） |
| UI | 1 套 | 手写体标题、纸质质感、褪色商店街配色 |
| 美术基调 | — | **低饱和、暖灰、洗褪色的夏天**。禁止过曝与小清新滤镜——本作要「脏一点」才真实 |

**关键美术要求**：
- 汐浦町必须**画得让人想住**（前两章），破败感靠细节（卷帘门的锈、招牌缺字），不靠惨
- 栞的立绘在第五章后要有**肉眼可辨的变化**：眼下阴影、手腕细了一圈、校服松了（不做说明，让玩家自己发现）

## 六、音乐与音响

| 项目 | 规格 |
|---|---|
| 主题曲 | 1 首（人声，日文/中文双版本） |
| BGM | 28–32 首 |
| 音响 | 蝉鸣（多时段变体）、雨（6 种强度）、海（按潮位分 3 种）、町内放送、自动贩卖机、便利店门铃 |

**「同一旋律的三次变奏」结构（本作音乐的核心设计）**
> 栞的主题旋律，在全作中出现三次：
> 1. **夏**（钢琴 + 弦乐，明朗、缓慢，第一章）
> 2. **冬**（只剩钢琴单音，缺了第 3 小节——因为她哥哥那段她跳过去了，第三章）
> 3. **空房间**（完整版，无伴奏，终章遗物场景 —— **她终于把它弹完了**）

**配音方案（预算现实）**
- 方案 A（推荐）：**关键场景全语音 + 日常部分语气词**，约 8,000–12,000 句
- 方案 B：全语音，约 22,000 句（成本 ×2.5）
- 优先配音场景：样张 1 / 3 / 4 / 5 / 6 / 7 / 8
- **关于栞的配音指示**：不要配出「虚弱」。她**全程听起来都是健康的**——只有玩家二周目回头看，才会发现她换气的频率不对。这是本作最狠的一个声音设计。

## 七、体验与无障碍

- 已读跳过、自动播放、文字速度（含超慢速）、历史记录回滚（100 句）
- 字号 3 档 / 色弱模式（对话框与潮汐表配色）/ 单声道音响
- **章节回放**：解锁后可直接跳章节
- **CG 鉴赏 / 信件抽屉 / 潮汐表存档**
- **「静音模式」**：一键关掉全部环境音，供受不了蝉鸣与心跳声的玩家使用
- 存档警告：终章前弹出一次「本作部分内容涉及疾病与死亡，建议在状态良好时游玩」

---

## 八、时长控制（防止「玩一下就腻」）

- 单章 60–90 分钟，每章都有独立的情感闭环（起→日常→小高潮→留白）
- 章节末必须有**一个小钩子**，但**不做廉价悬念**
- 日常文本允许「无意义对话」（聊便利店新品、抱怨天气）——**这正是日常流的必需品**，但单次不超过 12 句
- 全程无重复刷取、无日常任务、无好感度数值条（好感用「回忆点」隐式表达，不显示数字）
